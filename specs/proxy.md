# 本地代理服务

## 服务基本信息

- 默认监听 `127.0.0.1` 的可配置端口，不暴露到局域网
- 客户端只需配置一个统一 Base URL（如 `http://127.0.0.1:port`），无需按协议区分
- 支持普通 HTTP 请求和 SSE 流式响应透传
- 不强制接管系统代理；推荐用户在 AI 工具中配置本地 Base URL

## 协议识别

代理根据请求 path 自动匹配协议类型：

| 协议 | 匹配路径 |
|------|----------|
| OpenAI | `/v1/chat/completions`、`/v1/completions`、`/v1/embeddings` |
| Anthropic | `/v1/messages` |
| Gemini | `/v1beta/models/*` |
| Custom | 用户自定义路径匹配规则 |

- 若 path 无法匹配任何已知协议，返回 404 并提示未识别的 API 路径
- `/v1/models` 是代理自身提供的本地服务接口，不透传到上游

## 本地服务接口

### `/v1/models`

返回当前可用的模型列表（MVP 只有一个），方便支持模型列表拉取的工具自动发现。

响应格式兼容 OpenAI Models API：

```json
{
  "object": "list",
  "data": [
    {
      "id": "default",
      "object": "model",
      "created": 0,
      "owned_by": "one-switch"
    }
  ]
}
```

> MVP 固定返回一个名为 `default` 的模型。架构上支持多模型，未来扩展时直接增加即可。

## 路由策略

### MVP 单模型模式

MVP 版本只有一个逻辑模型（内部名称 `default`），不暴露多模型管理功能。

- 无论客户端请求体中 `model` 字段写什么，都统一路由到当前唯一的逻辑模型
- 转发到上游时，`model` 字段会被替换为该绑定配置的**上游实际模型 ID**（每个 Model Binding 上配置）
- 客户端无需关心上游实际模型名，统一使用任意值（或 `default`）即可

> 架构上保留完整的多模型能力（LogicalModel 表、多绑定、按 model 名匹配），MVP 只是在 UI 和路由入口处限定为单模型。未来开启多模型时，只需放开 UI 和路由匹配逻辑，底层无需改动。

### 路由步骤

1. **协议识别**：根据请求 path 自动匹配协议类型
2. **模型确定**：MVP 固定使用唯一的逻辑模型（忽略请求中的 model 名）
3. **绑定选择**：按优先级选择该模型在此协议下的绑定
4. **模型名替换**：将请求体中的 model 替换为绑定配置的上游实际模型 ID

### 过滤规则

- 被标记为冷却、禁用或达到手动额度阈值的 Provider 下的绑定直接跳过
- 如果该逻辑模型在请求协议下没有可用绑定，返回"当前协议下无可用模型"的错误响应

### 切换规则

- 同一请求不在同一绑定上重复重试；失败后切换到同协议下的下一个候选绑定
- 所有候选都失败时，返回最后一个上游错误，并在日志中聚合所有尝试

## 可切换错误分类

| 类型 | 行为 | 说明 |
|------|------|------|
| 网络错误、连接超时、响应头超时 | 自动切换 | 上游不可达或响应慢 |
| 408、429、5xx | 自动切换 | 上游明确不可用或限流 |
| 模型不存在 | 自动切换 | 该供应商绑定的上游模型 ID 可能配置错误 |
| 401 / 403 | 自动切换 + 告警 | 切换并标记该供应商配置可能错误 |
| 400 类请求格式错误 | 不切换 | 换供应商也不会成功 |

错误分类应可配置，MVP 提供合理默认值。

## 流式请求切换边界

- **可以切换**：尚未收到上游响应头，或上游返回错误状态码且响应体尚未发给客户端时
- **不可切换**：一旦 200 响应头或 SSE 数据已经开始返回给客户端，不再切换，避免输出内容混杂
- 流式中途断开记录为供应商失败，但不向另一个供应商续传同一次请求

## 透传规则

- 代理透传时保留客户端请求的原始方法、请求头、请求体
- 转发目标地址以绑定配置的完整上游 URL 为准，不拼接客户端 path
- 注入 Provider 配置的认证头
- 响应原样返回，包括状态码、响应头、响应体
