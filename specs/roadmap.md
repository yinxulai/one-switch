# 版本规划与验收标准

## MVP（P0）

### 范围

- Mac / Windows 菜单栏应用
- 本地 HTTP 代理，支持非流式和流式透传
- 根据请求 path 自动识别协议（openai / anthropic / gemini / custom）
- 本地 `/v1/models` 服务接口
- Provider 增删改查、密钥安全存储、连接超时配置
- 逻辑模型管理；每个模型绑定配置协议类型 + 完整上游 URL + Provider + 优先级
- 协议感知路由：请求只在匹配协议的绑定中选择；模型在该协议下无绑定时自动绕过
- 网络错误、超时、429/5xx、401/403、模型不存在时自动切换到同协议下一个绑定
- Provider 冷却与基础健康状态
- 请求日志
- 服务开关、端口配置、开机自启
- 配置导入导出（密钥脱敏）

### 验收标准

#### 1. 基础代理验证

- [ ] 启动应用后，本地端口可访问
- [ ] 所有工具统一配置 Base URL 为 `http://127.0.0.1:port`，无需按协议区分
- [ ] OpenAI 工具请求 `/v1/chat/completions`，代理自动识别为 openai 协议并透传到对应绑定
- [ ] Anthropic 工具请求 `/v1/messages`，代理自动识别为 anthropic 协议并透传到对应绑定
- [ ] Gemini 工具请求 `/v1beta/models/*`，代理自动识别为 gemini 协议并透传到对应绑定
- [ ] 请求 `/v1/models` 返回本地逻辑模型列表及各协议可用状态，不透传到上游
- [ ] 流式请求能持续返回 SSE 数据，不被代理缓冲破坏

#### 2. 协议感知路由验证

- [ ] 逻辑模型只配置了 openai 协议绑定；通过 anthropic 协议请求该模型时，返回"模型在此协议下不可用"或自动绕过
- [ ] 逻辑模型同时配置了 anthropic 和 openai 绑定；通过 openai 请求时只选 openai 绑定，通过 anthropic 请求时只选 anthropic 绑定
- [ ] `auto` 聚合模型在某协议下第一个模型无可用绑定时，自动跳到同协议下下一个模型

#### 3. 自动切换验证

- [ ] 最高优先级供应商不可达时，请求自动切换到下一个供应商并成功返回
- [ ] 最高优先级供应商返回 429 或 500 时，请求切换到下一个供应商
- [ ] 最高优先级供应商返回 401 时，切换并在控制台提示该供应商鉴权可能异常
- [ ] 上游返回 400 请求错误时，不切换，直接返回客户端错误

#### 4. 流式边界验证

- [ ] 上游在响应头前失败，自动切换
- [ ] 上游已经返回 200 和部分 SSE 后断开，不切换到其他供应商，记录失败

#### 5. 健康状态验证

- [ ] 连续失败达到阈值后供应商进入冷却，后续请求跳过它
- [ ] 冷却结束后，新请求允许再次尝试该供应商
- [ ] 成功请求后连续失败计数重置

#### 6. 安全与隐私验证

- [ ] 服务默认只监听 `127.0.0.1`
- [ ] 导出配置时 API Key 已脱敏
- [ ] 本地日志中不出现完整请求体、响应体或明文密钥
- [ ] 关闭应用后代理端口释放
- [ ] 开机自启设置生效

#### 7. 跨平台验证

- [ ] macOS 菜单栏图标、菜单和控制台可用
- [ ] Windows 托盘图标、菜单和控制台可用

## P1

### 范围

- Linux 打包与托盘体验完善
- 手动额度阈值与用量统计
- 供应商测试连接能力
- 更细粒度的错误切换策略配置
- 请求 ID、日志筛选、日志导出
- 可选本地访问 Token

## P2

### 范围

- 更多协议路径预设（Ollama 本地、OpenRouter、Azure 等）
- 按延迟、成功率、权重或成本的智能路由
- Token / 费用统计（按协议解析用量，不做报文转换）
- 主动健康探测
- 多配置 Profile
- 本地 CLI 或无头模式
