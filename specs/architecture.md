## 核心概念

### Provider
一个模型服务渠道，包含名称、认证方式、密钥、默认超时、启用状态、冷却状态。

> Provider 不持有统一 Base URL，因为每个模型绑定各自配置完整地址。

### Protocol
代理自动识别的 API 协议类型，根据请求 path 匹配判定，无需客户端区分 Base URL。

| 协议 | 特征路径 |
|------|----------|
| OpenAI | `/v1/chat/completions`、`/v1/completions`、`/v1/embeddings` |
| Anthropic | `/v1/messages` |
| Gemini | `/v1beta/models/*` |
| Custom | 用户自定义路径匹配规则 |

> `/v1/models` 不作为上游透传路径，而是代理自身提供的本地服务接口。

协议仅用于路由过滤，代理不解析任何协议的报文结构。

### Logical Model
对外暴露的统一模型名，例如 `auto`、`gpt-4o`、`claude-sonnet`。客户端通过请求体中的 model 字段（各协议自行携带）指定。

### Model Binding
逻辑模型在某一协议下到具体上游的绑定，是路由的最小单元。

每个绑定包含：
- 所属逻辑模型
- 协议类型
- 完整上游 URL（含 path 和 query）
- 所属 Provider
- 优先级
- 启用状态

一个逻辑模型可以在多个协议下各有若干绑定。

### Route
一次请求的路由决策结果，包含协议、逻辑模型、候选绑定列表、尝试顺序、失败原因。

### Attempt
一次上游调用尝试，包含绑定、耗时、HTTP 状态、错误类型、是否流式。

### Health State
Provider 级别的健康状态，包含连续失败次数、冷却截止时间、最近成功时间。

## 零协议转换原则

1. **不解析、不修改、不重写**请求体和响应体。不替换 JSON body 中的 model 字段，不增删协议特有字段。
2. 代理仅做三件事：
   - 根据请求 path 识别协议
   - 根据请求体中的 model 名（原样读取，不解析结构，仅提取字符串值）匹配逻辑模型
   - 将原始请求字节流透传到绑定配置的完整上游 URL，并注入认证头
3. 每个 Model Binding 配置的是该协议下的**完整上游地址**，代理不拼接路径。
4. 路由过滤：请求通过某协议进入时，只考虑该协议下的绑定。如果逻辑模型在该协议下没有任何启用的绑定，则自动绕过该模型。
5. 同一逻辑模型可以同时绑定 OpenAI 格式的供应商和 Anthropic 格式的供应商，但它们各自只在对应协议的请求中被选用，之间永远不会互相转换。
