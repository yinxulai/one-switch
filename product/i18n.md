# 国际化（i18n）

本文定义 One Switch 多语言支持的范围、语言模型、目录结构、错误契约与迁移顺序。

> **核心结论：界面文案可切换语言；日志与错误固定英文。** 诊断输出不查表、不依赖 locale、不随界面语言变化，这样日志可被复制到 issue、CI 或外部工具，跨语言混杂的问题不会出现。

## 1. 目标与非目标

### 目标

- 控制台界面支持 `zh-CN` / `en`，可即时切换、重启后保留。
- 诊断输出（运行日志、错误消息、管理 API 错误体、代理返回给客户端的错误）**始终英文**。
- 用户数据（供应商 / 模型 / 规则 / 逻辑模型的名称与描述）永不翻译。
- 用**编译期类型 + CI 门禁**把「漏翻、硬编码中文」变成可执行约束，而不是靠人肉 review。

### 非目标

- 不翻译代码注释（开发语言保持现状）。
- 不翻译上游请求 / 响应正文、Header、协议字段与状态枚举。
- v1 不支持两种以上语言、不做运行时下载语言包；目录随包发布。
- 不翻译 GitHub Releases 的发布说明（外部内容，另行处理）。

## 2. 三层语言模型

同一句「请求失败的信息」在不同层有不同命运，先把层切开，后面所有决策都从这里推导。

| 层 | 例子 | 语言 | 可切换 | 载体 |
| --- | --- | --- | --- | --- |
| **UI 文案** | 侧栏「逻辑模型」、按钮「保存」、空状态、toast | 跟随 `language` 设置 | 是 | UI 目录 |
| **诊断文案** | 运行日志、`AppError.message`、API `errorMessage`、代理错误 body | 固定 `en` | 否 | 英文源码字面量，不进目录 |
| **标识符** | `VALIDATION_ERROR`、`openai-completions`、`http-stream`、数据库列名 | 固定 `en` | 否 | 枚举 / Schema |

**日志和错误固定英文。** 理由：

1. 排障时日志要能被复制到 issue、CI、外部工具，混入中文后不可检索、不可全局搜索。
2. 错误码是**机器契约**，消息是**诊断信息**；面向用户的可读文案由界面层按错误码本地化（§5），两边职责不重叠。
3. 代理返回给 AI 客户端的错误由开发工具消费，英文是事实标准。

## 3. Locale 解析与持久化

### 设置项

`SettingsSchema`（`source/common/schemas.ts`）新增：

```ts
export const LanguagePreferenceSchema = z.enum(['system', 'zh-CN', 'en']).default('system')
export type LanguagePreference = z.infer<typeof LanguagePreferenceSchema>
```

- 持久化在 `settings` 表（`key = 'language'`），与 `listenHost` 等同级，走 `settings-store`。
- **放后端设置而非渲染层 localStorage**（theme 在 `app-ui-store` 里）：原生主进程（托盘、应用菜单、致命错误对话框）也要读语言，而主进程拿不到渲染层 localStorage。后端 `settings` 是主进程与渲染进程共用的唯一真相。
- 界面在「设置 → 外观与启动」卡片新增一行「语言」，遵循现有 `FormRow` 形态：一行一条、行内无图标、`divide-y` 分隔、白底。

### 解析规则

```
preference === 'system'
  → 主进程: app.getLocale()
  → 渲染进程: navigator.language
归一化：/^zh/ → 'zh-CN'；/^en/ → 'en'；其它 → 回退 'en'
```

- 设置项缺失 / 非法 → 回退 `'system'`。
- 目录缺 key → 回退 `en` 目录 → 再缺则原样返回 key 并只在开发期 `console.warn`。

> **待确认（默认 UI 语言）**：推荐 `system` 无法匹配时回退 `en`。若产品希望保留「默认中文」的历史行为，则回退 `zh-CN`。本文按回退 `en` 描述。

## 4. 目录（Catalog）与 key 规范

### 位置与形状

```
source/common/i18n/
  index.ts                 # resolveLocale / interpolate / createTranslator / plural
  types.ts                 # Locale、LanguagePreference、目录类型工具
  catalogs/
    ui.en.ts               # UI 目录结构真相源
    ui.zh-CN.ts            # Record<keyof typeof uiEn, string>
```

- **共享目录放 `source/common/i18n/`**：`@common` alias 已在 command 构建（`vite.config.ts` 的 `commonAlias`）与 render 构建（`renderAlias`）中配置，主进程与渲染进程都能 import，托盘 / 对话框不必再抄一份文案。
- 目录用 **TypeScript 模块而非 JSON**：可有类型、可写注释、可被编译期检查，符合仓库「零代码生成」取向。
- `ui.en.ts` 是**结构真相源**；`ui.zh-CN.ts` 声明为 `Record<keyof typeof uiEn, string>`，**缺一个 key 编译失败**，无需运行时完整性测试兜底。

### key 规范

- 层级点分：`<domain>.<area>.<element>[.<variant>]`，例如 `settings.appearance.theme.label`、`requestLogs.empty.title`、`errors.VALIDATION_ERROR`。
- key 全英文、小写驼峰，禁止拼音。
- **不拼接句子**：整句作为一条消息，用 `{placeholder}` 传参（`{count}` / `{port}` / `{model}` / `{field}`）。
- 复数走 `Intl.PluralRules`，目录值可为 `string | Partial<Record<Intl.LDMLPluralRule, string>>`；中文用单串即可。
- **数字 / 日期不写进目录**，用 `Intl.*` 按当前 locale 格式化；现有硬编码的 `toLocaleString('zh-CN', …)`、`toLocaleTimeString('zh-CN', …)` 改为传当前 locale。

### 不进入 UI 目录的内容

- 供应商 / 模型 / 规则 / 逻辑模型的名称与描述（用户数据，原样展示）。
- 请求正文、Header、协议字段、错误码本身、上游返回的错误文本。

## 5. 错误契约：错误码是契约，消息是英文诊断

### 现状问题

- `AppError.code` 类型是 `string`（未收窄到枚举）。
- `unwrap.ts` 直接 `throw new Error(result.errorMessage)`，服务端消息与界面语言绑死；一旦消息改英文，界面就会显示英文。

### 目标契约

1. **服务端只输出英文**：`AppError.message`、管理 API `errorMessage`、代理错误 body、`console.*` 全部英文。
2. **错误码是稳定契约**：`AppError.code` 收窄为 `ApiErrorCode`；`ApiErrorCodeSchema`（`source/common/schemas.ts`）是唯一枚举来源。
3. **本地化参数随错误返回**：`AppError` 已有 `details`，把其中**可安全序列化**的值作为 `errorParams` 暴露到 `ApiError`（如 `{ port, model, field }`），供界面拼装本地化文案，不把服务端英文句子当模板。
4. **界面按错误码本地化**：渲染层新增 `errors.<errorCode>` 文案（属 UI 目录）与 `localizeApiError(error)`；`unwrap` 改为抛携带 `errorCode` + `errorParams` + 英文 `errorMessage` 的 `ApiRequestError`。界面 toast 用本地化文案，诊断 / 详情面板保留英文原文。
5. **类型强制覆盖**：`const errorMessages: Record<ApiErrorCode, …>`，新增错误码不补文案就编译失败。

代理对客户端返回的错误（`writeJsonError`）保持英文——消费者是 AI 工具，不是本应用界面。

## 6. 日志规范

- 运行日志（`runtime_logs` / `console.*`）消息为英文，级别口径与脱敏要求仍以 [observability.md](./observability.md) 为准。
- 统一结构化风格：`[module] event key=value`，例如 `[proxy] attempt failed provider=xxx code=UPSTREAM_TIMEOUT`。
- **不引入日志目录、不做 locale 查表**；日志不受 `language` 设置影响。
- 现有中文日志逐条改写为英文；单测中断言中文消息的地方同步改为英文断言（见 §8 阶段 1）。

## 7. 界面集成

- Provider：`source/render/source/i18n/provider.tsx`，读取 `settings.language`（复用 settings 查询；切换后即时更新，无需重载）。
- Hook：`useTranslation()` 返回 `{ t, locale }`。
- **Provider value 必须 memoize**：仓库有「context value 进依赖数组导致级联重渲染」的历史坑（见 `render-state-architecture` 记录），`t` 的引用必须保持稳定。
- `document.documentElement.lang = locale`；原生窗口标题跟随语言。
- 数字 / 日期统一走 `Intl` 并按当前 locale 格式化。

### 原生（Electron 主进程）

- 托盘菜单（`tray-manager.ts`）、应用菜单（`Edit` / `View` / `Window`，`index.ts`）、`dialog.showErrorBox`、更新卡片文案本地化。
- 主进程 locale 来源：优先读 `settings.language`；启动早期数据库尚不可读时用 `app.getLocale()`。
- 原生 role 菜单保留 `role`，只本地化顶层 `label`。

## 9. 门禁（可执行约束）

模仿 `scripts/check-proxy-layers.mjs` 的做法，把规范变成 CI 可执行项，而不是只写在文档里的共识：

1. **ESLint 规则 `no-hardcoded-cjk`**（本地插件 `scripts/eslint-plugin-i18n.mjs`，接入 `scripts/lint.mjs`）：
   - 命中：字符串字面量、模板字面量、JSX 文本中的 CJK 字符。
   - 豁免（均在 `eslint.config.js` 里就地注明理由）：
     - 注释（解析器天然区分）；
     - `source/common/i18n/catalogs/**`（文案存放处）；
     - `*.test.{ts,tsx}`、`test-support.ts`（断言里的中文是数据，不是界面文案）；
     - `common/router/presets.ts`、`model-management/lib/provider-presets.ts`、`server/database/development-seed.ts`（预设 / 种子：写入即成为用户自己的内容，见 §4）；
     - `common/router/engine.ts`（trace / 决策依据是随请求落库的运行记录，不是可切换的界面文案）。
   - 为什么用 ESLint 而不是脚本：解析器天然区分注释与字面量，编辑器内即可即时提示。
2. **目录检查**（`source/common/i18n/catalogs.test.ts`）：
   - en 与 zh-CN key 集合一致（编译期已保证，测试兜运行期数据）；
   - 无空串、无 `TODO`、无未使用 key（扫描生产源码里的 key 字面量 + `errors.${}` / `failureReason.${}` 前缀豁免），并自检扫描文件数以防静默漏扫。
3. **错误码覆盖**：`Record<ApiErrorCode, …>` 编译期保证每个错误码都有本地化文案；**不设 `errors.UNKNOWN`**——目录里没有的错码直接退回英文诊断原文（见 §5 目标契约第 4 条）。

## 10. 决策摘要

| 议题 | 决策 | 理由 |
| --- | --- | --- |
| 引入 i18next 等运行时库 | **不引入**，自研约百行核心 | 无异步加载、无重格式化需求；与仓库「最小依赖 / 原生平台」取向一致；`Intl` 覆盖复数与格式化。`t()` API 稳定，未来可替换实现 |
| 目录格式 | TypeScript 模块 | 编译期类型 + 注释；避免 JSON 生成的构建步骤 |
| 诊断文案 | 英文源码字面量，不进目录 | 永不翻译，目录化只会增加间接层 |
| 错误本地化 | 错误码是契约，界面按码本地化 | 服务端保持语言中立，日志与外部消费稳定 |
| `language` 存放 | 后端 `settings` 表 | 主进程与渲染进程共用同一真相 |
| 默认值 | `system`，无法匹配回退 `en` | 待产品确认 |

## 11. 风险与开放问题

- **迁移量大**：渲染层字符串点集中在 `source/render/source/pages/**`；阶段 3 需逐页验收，重点看「英文字符串更长导致布局溢出 / 截断」。中英长度差异要专门检查。
- **测试基线**：大量单测断言中文消息，阶段 1 会触碰这些断言，需与实现同 PR 修改，避免中间态红。
- **默认 UI 语言**：`system` 回退 `en` 还是 `zh-CN` 需产品确认。
- **第三方 / 生成文案**：`runtime-settings` 的 release notes HTML、`date-fns` / `recharts`（图例、无障碍标签、月份名）等库内置文案需检查并补 locale。
- **发布说明语言**：GitHub Releases 内容是否按语言提供两份，另行决定。
