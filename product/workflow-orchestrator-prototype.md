# 流程编排器原型调研与方案（不接入接口）

## 目标
- 提供一个可拖拽节点的流程编排原型，用于讨论编排体验与能力边界。
- 支持条件判断、修改器、转换器、队列转发四类核心节点。
- 在本地浏览器内执行模拟，不调用服务端 API，不改动现有代理行为。

## 为什么先做原型
- 编排体验高度依赖交互细节，先做 UI + 本地执行可以快速收敛需求。
- 不接接口可避免提前锁死服务端数据模型，减少返工。
- 可用真实结构的 JSON 输入，验证规则表达力与可读性。

## 可选实现路径对比

### 路径 A：纯前端原型（本次采用）
- 形式：页面内维护节点数组，拖拽排序，本地执行引擎逐节点运行。
- 优点：开发最快、可视化反馈最直接、讨论成本低。
- 风险：与未来服务端执行细节可能存在语义差异。

### 路径 B：前端 + 本地 mock IPC
- 形式：前端编辑，执行请求走 Electron IPC 到 mock runtime。
- 优点：更接近线上运行链路。
- 风险：原型阶段复杂度高，调试面更大。

### 路径 C：直接接入真实 proxy 流水线
- 形式：节点配置直接进入 proxy 模块执行。
- 优点：结果最真实。
- 风险：实现成本高，需求未稳定前返工风险最大。

## 原型能力范围（v0）
- 节点库：
  - 条件判断 `condition`
  - 修改器 `modifier`
  - 转换器 `transformer`
  - 队列转发 `route-queue`
- 编排画布：
  - 节点按顺序执行
  - 支持拖拽排序
  - 支持启用/禁用
  - 支持增删节点
- 运行面板：
  - 输入 JSON payload
  - 输出变更后的 payload
  - 显示目标队列
  - 显示逐节点执行轨迹

## 节点语义（v0）

### condition
- 字段：`path`, `operator`, `value`, `onFalse`
- operator：`contains | eq | gt | exists`
- 行为：命中继续；不命中根据 `onFalse` 选择 `continue` 或 `stop`。

### modifier
- 字段：`path`, `value`
- 行为：将值写入路径，支持字符串、数字、布尔、JSON 字面量解析。

### transformer
- 字段：`fromPath`, `toPath`, `mode`
- mode：`trim | uppercase | lowercase | stringify`
- 行为：读取源字段并转换后写入目标字段。

### route-queue
- 字段：`queueId`
- 行为：设置目标队列（本地模拟结果字段，不触发真实转发）。

## 评审关注点
- 节点命名与配置是否足够直观。
- 条件节点的失败策略是否需要扩展（例如分支流转）。
- 转换器是否需要链式函数（例如 trim 后再 uppercase）。
- 队列节点是否应只允许一个，还是允许覆盖式多次设置。
- 执行轨迹展示是否满足排错需求。

## v1 预演（下一阶段建议）
- 增加“分支节点”和“合流节点”，支持 DAG 而不只是线性链。
- 为节点引入 schema 校验与错误高亮。
- 增加“测试用例集”，批量回放样例并比较结果。
- 接入持久化（本地存储或数据库），支持流程版本化。
- 再与 proxy runtime 对齐执行语义，逐步替换本地执行器。
